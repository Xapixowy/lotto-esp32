# Domain docs

## Before exploring

Read the root GLOSSARY.md and relevant decisions in docs/adr/.
If they do not exist, proceed silently. Domain modeling creates
them as terms and decisions are settled.

## Layout

- GLOSSARY.md: shared domain terminology.
- docs/adr/: numbered architecture decision records.

## Vocabulary and decisions

Use the glossary's terms in issues, code proposals, and tests.
Flag terminology gaps for domain modeling.

If a proposal conflicts with an ADR, identify the conflict
and explain why the decision should be reconsidered.
